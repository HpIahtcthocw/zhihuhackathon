# 《岔路口・知乎围炉》产品说明计划书

> 知乎黑客松 2026「跨次元游乐场：AI 游戏与互动叙事」参赛作品
> 提交时间：2026-09-15



***

## 一、一句话产品

**从知乎热榜选一个真实困境（或写下你自己的），四位 AI 孵化的知乎答主围炉质询你、和你对线，再陪你把这一年的命运推演完 —— 最后得到一张可以晒的朋友圈命运卡。**

用知乎的争议做游戏的关卡，用知乎答主的 "味" 做游戏的 NPC，用玩家的真实人生做游戏的剧情。



***

## 二、核心思路

### 1. 为什么是 "围炉"？

知乎最迷人的不是答案，是**评论区里吵起来的那一刻**—— 答主立场的对撞、评论区 "反对最高票" 的拆台、匿名用户讲出的扎心细节。我们把这种社区特有的 "多人对线" 抽象成游戏机制：



* 不是单机问答，而是**一场围炉辩论**：四位立场真正对立、各有职业身份的答主（安稳派 / 闯荡派 / 过来人 / 风险派）围绕玩家的问题交锋；

* 玩家不是旁观者，是**被质询的对象**—— 答主会引用玩家处境的原话回怼（"你说存款只够撑半年 ——"）；

* 玩家可以出应对卡，也可以**亲口打字回怼**，AI 以答主人格即兴接招。

### 2. 为什么是 "真实困境"？

知乎上有大量真实的、无解的、正在发生的人生抉择 —— 裸辞、异地恋、原生家庭、转行、存钱焦虑。这些不是 "虚构关卡"，是**用户本来就会搜的问题**。

产品因此形成双入口：



* **热榜入口**：知乎开放平台实时拉取争议问题，用户一键入席；

* **自定义入口**：用户写下自己的困境，AI 现场编译成专属围炉。

### 3. 为什么是 "这一年"？

游戏不只是给结论，而是把选择**推演到一年后**：12 个月事件卡逐月展开，延迟后果引爆（"第 3 个月：存款见底"），四维 "体温"（存款 / 心态 / 机会 / 家人）实时变化，最坏结局是**现实危机**而不是 Game Over。让玩家在虚拟里先把这一年的代价想清楚。

## 三、技术方案

### 架构总览



```
┌─────────────────────────────────────────────┐

│  前端：public/game/index.html（单文件，无构建依赖） │

│  - 四答主围炉 UI / 事件卡时间线 / 命运卡 PNG     │

└────────────────────┬────────────────────────┘

&#x20;                    │ fetch

┌────────────────────▼────────────────────────┐

│  Next.js 14 + TypeScript（EdgeOne Makers 部署）│

│  app/api/forge       困境 → 围炉编译器（核心）   │

│  app/api/rebuttal    打字回怼：答主即兴接招      │

│  app/api/hot         知乎实时争议拉取 + 1h缓存   │

│  app/api/constraints 三张约束牌动态生成          │

│  app/api/auth        知乎登录态（可选）          │

└────────────────────┬────────────────────────┘

&#x20;                    │

&#x20;  ┌─────────────────┼─────────────────┐

&#x20;  ▼                 ▼                 ▼

知乎开放平台      LLM（通义千问      无数据库

zhihu\_search      OpenAI 兼容协议）   进程内缓存

热榜实时数据      编译/接招/推演       24h 防重复
```

### 关键技术点



| 模块     | 方案                             | 说明                                        |
| ------ | ------------------------------ | ----------------------------------------- |
| 困境编译   | LLM + JSON Schema 严格校验         | 四位答主、三轮质询、一次对线、12 月事件卡、4 种结局，一次生成结构化 JSON |
| 偏题检测   | 实体约束 + 原文引用校验                  | 保留用户困境关键实体（年龄 / 城市 / 金额），不得偷换主题；质询必须引用原话  |
| 24h 缓存 | sha1 困境键 + 进程内 Map             | 同一困境 24h 不重复编译，控制成本与延迟                    |
| 知乎数据   | 开放平台 hot\_list + zhihu\_search | 热榜 1h 缓存应对每日限额；搜索分批串行防限频                  |
| 离线兜底   | 内置 7 类话题池 + 模板剧本               | 断网 / 限频 / 编译失败永不 502，自动降级并明确标注            |
| 交锋判定   | 回复质量启发式评分                      | 玩家回应影响四维数值与后续事件走向                         |
| 部署     | EdgeOne Makers（Next.js 全栈）     | 国内可直连、免费、自动 HTTPS                         |

### 数据诚实性（硬约束）



* 热榜问题与赞同 / 评论数来自知乎开放平台实时接口；

* 答主为 **AI 孵化的观点人格**，页面明确标注「AI 实时编译（非知乎历史）」；

* 不伪造赞同数、不冒充真实用户、不虚构历史事件；

* 离线快照与模板剧本均明确标注「原型模板 / 历史抓取」。

## 四、与知乎生态的契合度

### 1. 内容侧：把知乎的 "内容资产" 变成游戏关卡



* 热榜议题即关卡池，知乎每天产生的新争议自动成为游戏新内容，**内容零成本且永远新鲜**；

* 答主话术基于知乎高赞回答的写作范式（"先说结论"" 泻药 ""利益相关"" 反对最高票 ""不请自来"），原生知乎味。

### 2. 生态侧：双向引流



* **知乎 → 游戏**：用户从热榜 / 搜索发现自己的困境，一键入席推演；

* **游戏 → 知乎**：每张命运卡附议题原文链接与答主观点溯源，玩家晒卡即带动知乎原问题讨论。

### 3. 平台侧：AI 时代知乎内容互动的新形态



* 知乎沉淀了中文互联网最密集的 "真实人生困境问答"，本产品用 AI 把它变成**可玩、可推演、可分享**的互动叙事；

* 呼应「跨次元游乐场」主题：现实话题 × AI 叙事 × 游戏化交互。



***

## 五、玩法闭环（约 4 分钟）



1. **选题**：知乎热榜实时争议 / 写下自己的困境；

2. **底牌**：三张约束牌（存款水位 / 时间窗口 / 退路）动态生成，决定初始处境；

3. **编译**：LLM 实时把困境编译成围炉（四位答主 + 三轮质询 + 对线 + 12 月事件 + 四种结局）；

4. **围炉**：答主引用真实社区观点风格质询，玩家出应对卡或打字回怼；

5. **推演**：逐月滑动事件卡，延迟后果引爆，四维 "体温" 实时变化；

6. **命运卡**：称号 + 判词 + 决策时间线，一键生成可分享 PNG。

## 六、当前状态与未来规划

* 完整 4 分钟玩法闭环，线上部署可体验；

* 知乎真实热榜接入（多类别 7 类话题 + 分类徽标）；

* AI 围炉编译 / 打字回怼 / 事件卡推演 / 命运卡生成；

* 数据诚实标注与离线兜底。

### 规划中



* 知乎账号登录后按真实关注 / 收藏推荐议题；

* 命运卡一键发布到知乎想法 / 回答（带议题溯源）；

* 多局数据沉淀：同一困境不同选择 → 结局对比；

* 议题共创：用户可投稿真实困境进入热榜池。
